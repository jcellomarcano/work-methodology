# Feature: kit-init

**Objective.** One command initializes the whole kit in a target repo, leaves nothing out, suggests the external tools that help (Engram, Context7, …), and proves the ways of working actually run: a wiring doctor plus a full-loop smoke on a throwaway copy.
**Branch.** `feat/kit-init`, from `feat/methodology-benchmark` after 75fc2e8 (DOC-002/003 committed first, user decision). Personal and client files (`07-communication/bench/tmp/`, `odd/tasks/review-comment-post.md`) are never staged.
**Tests.** `cd 03-tools && METODO_MEMORY=off python3 -m unittest discover tests` (baseline at 75fc2e8: 525 OK, 4 skipped, 2 expected failures); docs caps with `python3 lib/docs_lint.py config/docs-caps.json`.

## Specs

Quoted fragments are the user's exact words (Spanish, 2026-10-15); the requirement text is English.

- **S1 One command, nothing left out.** "que con un comando, no se si eria una skill o que, pueda hacer el trabajo de inicializar todo el kit que no quede nada por fuera". One entry point takes a target repo from zero to a working kit instance. Every item of `05-adopt/checklist.md` is either done by the command or printed as an explicit pending human step with the file to fill in; none is silently skipped.
- **S2 Form.** User chose "Script + skill fina (recomendado)": a deterministic `bin/init.sh` does every scriptable step; a thin skill conducts the owner interview (property hierarchy, critical properties, invariants) and calls the script. Skills wrap scripts; the model never re-derives what the script prints.
- **S3 Suggestions.** "sugerir cosas como el uso de memoria de engram el context7, etc". User chose "Detectar y sugerir (recomendado)": the command detects whether each helper (Engram, Context7, gentle-ai, and the other optional tools the kit uses) is installed and configured, and prints the exact command to enable what is missing. It never installs anything global.
- **S4 Ways of work must work.** "pero siento que the ways of work necesita funcionar". Covered by S5, S6 and S7 together (user selected all three).
- **S5 Wiring doctor.** User chose "Doctor de cableado": a check proving hooks, MCP server, agents, skills and config are installed and respond, with a clear FAIL naming what is missing and how to fix it.
- **S6 Full-loop smoke.** User chose "Smoke del loop completo": on a throwaway copy, card → receipt start → capture → finalize runs end to end, proving the flow works. The user's repo is never mutated.
- **S7 Fix what blocks it.** User chose "Arreglar lo roto que lo bloquea": English/Spanish labels in the validator and schemas, `metrics --save`/baseline, the skill that is not installed, the hardcoded `origin/develop`, and the Pi hook gaps.
- **S8 Personal stays personal.** "lo PERONSAL queda en perosnal". The command never copies, installs or reads the owner's personal assets (any path matching `*.personal.*` or under a `personal/` folder, and `07-communication/bench/tmp/`); they stay where they are, untouched.
- **S9 Language.** Every artifact (code, docs, commits, reports) is English; chat with the user is Spanish (user, 2026-10-15).
- **S10 Purpose: a fair kit-vs-vanilla comparison.** "the goal, is to see how benefits will bring use this work methodology, vs use vanilla". The init exists so the kit arm of `08-benchmark` really runs the kit: Phase 1 measured partial adoption (hooks ran in 42/85 sessions of one repo, 0 elsewhere) and the PR 176 pilot's kit arm never ran the kit (`odd/tasks/methodology-benchmark.md` L13). The doctor and the smoke emit machine-readable evidence that the kit is installed and the loop ran, usable by the benchmark to accept or mark `invalid-arm` a kit run; `08-benchmark` docs point to the init as the kit arm's setup step.
- **S11 Measure and update the README on every important change.** "cada vez que se hagan cambios iemportantes, que se midan y se actualice el Readme". The README carries a measured-status block produced by a script (never typed by hand: evidence or silence): kit test count and result, docs caps, and the doctor, smoke and init readiness on a throwaway fixture repo, each with its tag and the kit sha it was measured at. A test fails when the block is stale against the code it describes, so an important change cannot land without re-measuring and updating the README. The rule is also written into the methodology so it applies to every project using the kit.

- **S12 Gradle build files are guarded.** User chose "las 3" (A) after the Gradle digest found that `shared_build_files` / `guard_paths.py` miss `gradlew*`, `gradle/wrapper/**`, `gradle/verification-metadata.xml`, `buildSrc/**`, `build-logic/**` and module build files outside `app/`, and that `full_required_globs` `**/build.gradle` misses `.kts`. A subagent can no longer edit any Gradle build file, and any of them triggers the full battery.
- **S13 Unplug on demand.** User chose "las 3" (B): one command removes everything the kit installed in a repo, for Claude Code and pi, never touching files it did not install; the instance and audit folder stay unless explicitly purged; the doctor confirms nothing is left.
- **S14 LLM entry point.** User chose "las 3" (C): root `AGENTS.md` and `CLAUDE.md` tell any agent where to start (`CONTEXT-PACK.md`), how to plug in and unplug, and the kit's own working rules.
