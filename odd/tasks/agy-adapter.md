# Feature: agy-adapter

**Objective.** The kit installs into a target repo for Google Antigravity CLI (`agy`) as a third runtime next to Claude Code and pi: roles as subagents, skills, guard hooks, the `metodo` MCP server, with init, doctor and uninstall support.
**Branch.** `feat/agy-adapter` from `feat/goal-contract` @ `d582995`, worktree `~/work-methodology-worktrees/agy-adapter`. This is a hand port of the Spanish tree's `feat/agy-adapter` (`fc3f968..5f3129b`, 10 commits) under `odd/tasks/tree-unification.md` S1 and L6: the two trees share no git history. Delivery `ask-on-risk`. Runner: `cd 03-tools && METODO_MEMORY=off python3 -m unittest discover tests`; docs: `python3 03-tools/lib/docs_lint.py 03-tools/config/docs-caps.json --tokens 03-tools/config/token-caps.json`; status: `03-tools/bin/kit-status.sh --write` then `--check`.
**Risk.** Items 2 (guard globs, a hook bridge) and 5 (installer): independent verifier at the end.

## Specs

- **S1 Request.** "Crea todo para que funcione dentro de AGY mi metodologia". Accepted plan: a third adapter, per repo, in `.agents/`, hooks bridged onto the existing Python scripts.
- **S2 Spike.** On a throwaway clone, measure agy's real tool names and args, whether a `PreToolUse` deny is honoured, whether `SessionStart` can inject context, where MCP loads (workspace or global only), and whether the kit's skill frontmatter and sizes are accepted.
- **S3 Roles.** `render_agents.py --target agy` renders every `01-roles/agents/generic-*.md` into an agy subagent (`name`, `description`, mapped `model`, contract as prose, role marker).
- **S4 Hooks.** A bridge maps agy hook events and tool names onto the scripts in `03-tools/hooks/hooks.settings.json` and translates their output into agy's stdout decision; the matrix stays in parity with `hooks.settings.json` by test. `.agents/**` becomes always-forbidden for writers.
- **S5 Installer.** `install-agy.sh <repo> [--tools D] [--uninstall]`: everything lands in one workspace plugin `.agents/plugins/metodo/` (plugin.json, agents/, contracts/, skills/, hooks.json, mcp_config.json, rules/AGENTS.md; `contracts/` added on this tree, L10); idempotent, byte-identical uninstall, skill list read from `install-claude.sh`, git-exclude, server selftest. Nothing is written outside the repo (L3: a workspace plugin's MCP server starts per repo).
- **S6 Runtime lists.** `agy` is accepted by `install.sh`, `init_kit.py`, `doctor.py`, `suggest.py`, `config/suggestions.json`, `render_agents.py`. agy does not read `.mcp.json`, so the claude/pi shared-entry keep check stays two-way (L3).
- **S7 Doctor.** `doctor.py` checks agy agents, skills, hooks, MCP; `--absent` covers agy.
- **S8 Docs.** `00-principles/agy-adapter.md` (capped), a matrix row in `runtime-adapters.md` (built on both trees as a pointer line above the matrix, L11), checklist and tools README updated, README status re-measured.
- **S9 Port rules (this tree).** Source of every change: the Spanish repo `~/metodologia-de-trabajo`, branch `feat/agy-adapter`, read with `git -C ~/metodologia-de-trabajo show <sha>`. A port adds to this tree's files and keeps its native work (router, done gate, tool-output filter, warn channel, activation profiles, launch gate); it never replaces a file with the Spanish copy. The bridge covers this tree's hook matrix, which is larger than the Spanish one: every entry of `03-tools/hooks/hooks.settings.json` at `d582995` has a row or a stated reason for having none, and agy's `invoke_subagent{TypeName,Prompt,Role}` reaches the launch gate (`guard_spawn.py`) as a `Task` launch. The two verifier blockers of the Spanish L7 (B1 `.agents/**` out of build-file risk, B2 MCP configs read per runtime) are part of the port, not a later correction. `docs/08-harnesses.md` and the two `README.md` lines that say Antigravity works by hand with no installer are updated to the adapter; the facts measured on agy stay tagged with the version they were measured on (1.4.7, 2026-10-26, Spanish tree) and are not re-measured unless a task says so.
