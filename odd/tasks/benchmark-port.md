**Objective.** One benchmark on the canonical tree: the English `benchmark-skill` work (session report, A/B runner, portable skill) sits on the current chain, and the instance side that only the Spanish tree had (collector, `SessionEnd` queue, init step, doctor checks, MCP tool) is ported onto it.
**Branch.** `feat/benchmark-port` from `feat/agy-adapter` @ `c316f98`, worktree `~/work-methodology-worktrees/benchmark-port`. Delivery `ask-on-risk`: the forecast is about 1700 authored lines on top of the replay, so the chain strategy is asked before any push. Runners: `cd 03-tools && METODO_MEMORY=off python3 -m unittest discover tests`; `cd 08-benchmark && METODO_MEMORY=off python3 -m unittest discover tests`. Risk: items 3 and 5 (a new entry in the hook settings every installed repo receives, a new init step, a detached process) → independent verifier at the end.

- **S4 Collector.** `03-tools/bin/bench.sh <sub> <repo> [--tools DIR]` runs `03-tools/lib/bench_collect.py`; the instance is `--tools`, else `METODO_TOOLS`, else the script's parent; a usage error exits 2. `collect` reads the queue and sweeps the repo's transcript dir (`transcript_metrics.transcript_dir`, root `CLAUDE_PROJECTS_DIR`, default `~/.claude/projects`); it writes one row per session at `out/bench/sessions/<id>.json` and measures again only when the transcript is newer; it writes the aggregate `out/bench/data/sessions.json` in the `transcript_metrics` payload shape; it prints one line `{failed, measured, queue_left, skipped}` and exits 0 with failures counted; a held `.lock` prints `{"locked": true}` and exits 0. No prompt or reply text, no absolute path, same bytes across runs.
- **S5 Report, status, adopt.** `report` chains collect, `git_metrics`, `kit_telemetry` and `phase1_report` into `out/bench/{data,report}`, prints the `.md` path and exits 1 if the last one fails. `status` prints JSON `{enabled, adoption, sessions_measured, kit_sessions, queue_left, last_collect}`. `adopt` writes `out/bench/adoption.json` once (`installed_at`, `repo` from the resolved path, `label`) and prints `recorded` or `kept`. `phase1_report` reads `data/adoption.json`: the boundary becomes Measured, `first_marker: install`, and `status.adoption` is reported.
- **S6 A/B from the instance.** `bench.sh ab <repo> <run|judge|report> [args]` forwards to the instance's `bench/lib/bench_cli.py` as `ab`, `judge` and `report`. *Assumption (parent):* the Spanish `ab` ran `pr-review-ab.sh`; with the English runner as the base it forwards to that runner instead, and `pr-review-ab.sh` stays unwired.
- **S7 SessionEnd queue.** `hooks.settings.json` gains a `SessionEnd` entry (kit marker, timeout 10) that runs `03-tools/hooks/bench_queue.py`. The hook writes `out/bench/queue/<session_id>.json` as `{session_id, transcript_path}`, rewrites it on repeat, queues an empty path too, and exits 0 silently on a bad id or bad stdin. It spawns a detached `bench.sh collect <repo>` (`CLAUDE_PROJECT_DIR`, else `cwd`); `METODO_BENCH_NO_SPAWN=1` stops the spawn; with no `bench.sh` the item stays queued. The config key `bench.enabled` (absent means on) gates the hook, the init step and `status`. Merging and removing the kit entry keeps the owner's own `SessionEnd` hooks. The measurement is Claude Code only: the agy bridge lists the entry as exempt with that reason, and pi does not carry it.
- **S8 Init, doctor, MCP.** `init.sh` gains the step `bench` after `baseline` (adopt, then collect; `done`, `warn`, `fail` or `skipped`, with a deterministic detail) and the flag `--no-bench` (usage, parser, dry-run line). The doctor gains `bench.wired` (PASS or WARN, not required) and `bench.used` with `counts {sessions, hooks, agents, mcp, skills, engram}` for this repo; `claude.hooks` skips the bench entry. On a runtime with no Claude Code install (`--runtime pi` or `agy`) the step is `skipped` and both checks are SKIP, so the kit prints no warning that nothing can clear (rewritten 2026-11-13, L5). The MCP server gains the tool `bench_report` (a job; summary `out/bench/report/phase1-baseline.json`). Uninstall keeps `out/bench/`.
- **S9 Skill and documents.** `harness-benchmark` stays the one benchmark skill and stays portable; it gains a short section for a repo with a kit instance (`bench.sh status`, `collect`, `report`, the MCP tool) with the scope stated: Claude Code only, `--no-bench` keeps the hook, only `bench.enabled: false` stops it. `03-tools/README.md` and `05-adopt/checklist.md` document the step, `bench.sh` and `--no-bench`. *Assumption (parent):* the Spanish tree shipped a second skill, `benchmark-del-kit`; here its content joins the existing skill, so the model has one benchmark trigger instead of two.

The collector is `bench_collect.py` and the hook is `bench_queue.py`, because `bench.py` and `bench_session.py` already name other programs here. One transcript root variable, `CLAUDE_PROJECTS_DIR`. Test-first with one RED run per behavior. Install, init, doctor and suggest output for Claude Code, pi and agy changes only by the additions named in S7 and S8; any other change to existing output is a blocker.
