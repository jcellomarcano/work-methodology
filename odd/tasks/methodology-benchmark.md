# Feature: methodology-benchmark

**Objective.** A strict, reproducible before/after audit of this work-methodology kit (ODD, RDD, Engram memory, gentle-ai, judges, deterministic scripts, lints, model router) against a vanilla Claude Code harness, with numbers that say what works, what does not, and what is bullshit; presented as a product to other developers (report + slides).
**Branch.** `feat/methodology-benchmark`, chained on `feat/review-comment-post` (its uncommitted files are never staged). Only `08-benchmark/**` and this document are committed here.
**Delivery.** `ask-on-risk`; forecast well above 400 authored lines, so a chain of PR slices (one per task group) will be proposed when the first slice closes. Test runner: `cd 08-benchmark && python3 -m unittest discover tests` (stdlib only, no network, raw transcripts never committed).
**Coordinator.** Claude Fable 5.1 coordinates (user decision 2026-10-13). The model under test is identical across all arms of Phase 2 and is never the coordinator.

## Specs

Quoted fragments are the user's exact words (Spanish, 2026-10-13); the requirement text is English.

- **S1 Language.** "todo lo que se vaya a trabajar y hacer becnhmarking se haga 100% en ingles y todos los documentos se hagan en ingles." Every benchmark artifact (code, docs, reports, slides, commit messages) is English.
- **S2 Before/after.** "benchamrk before and afetr y ver como la metodologia de trabajo realmente mejora vs un harness normal o un framework normal" ... "necesito datos de before and after y haber de como esto peude impactar, negativa o positivamente en el trabajo". Every metric is reported before vs after (Phase 1) and vanilla vs kit (Phase 2), negative results included.
- **S3 Plugin impact and ablation.** "que tanto el plugin de engram y gentle ai esta ayudando en eso y medirlo, por que, como, cuando." ... "Cual es el impacto de engram y que tan fundamental es, se peude usar otras cosas, sin engram es factuble manejar este repo?" Engram and gentle-ai are measured as separate variables; Phase 2 has a kit-without-Engram arm; the report answers whether the repo is workable without Engram and what could replace it.
- **S4 Process data.** "que pasaba antes de framework en la propuesta de la taria, como se maneja el prompt. los test, como se maneja el delivery". Baseline describes task proposal, prompt handling, tests and delivery before and after the kit, from evidence.
- **S5 Influences.** "de donde vienen las influencia (uncle bob, software wasteland, iso 24495, referencias, buscar ser determinista ODD, RDD, memoria, context". The report traces each kit mechanism to its stated influence and source, each citation checkable.
- **S6 Context and verbosity metrics (company AI expert).** "lo mas improtante es que peudas medir com se maneja el contexto, en numeros como vas, la verbosidad del modelos, cuando te repsonde, que tanto improve hay en el codigo, por ejemplo, si hace un PR, que tanto va alineado con los estandares del repos sin romper el espacio del context, que tanto cambia en encontrar cosas que estan mal, o posibes errores". Numeric metrics for: context occupancy per session, tokens in/out and cache, assistant verbosity, response latency, code quality delta per PR, alignment with repo standards, defects found.
- **S7 Judges and adversaries.** "Como los juez, adversarios, blind spots y las RDD, SDD, y ODD, junto con test deterministas de uncle bob inpiration ayudan". Measure the contribution of blind dual judges, refuters, RDD, SDD, ODD and deterministic tests (defects caught, false positives, cost).
- **S8 Delivery communication.** "como es la parte de comunicacion a la hora de hacer el delivery". Measure delivery communication (PR descriptions, comments, incident reports) against the kit's templates and lints.
- **S9 Incidents and epistemic labels.** "la parte de hacer inicdencias, y como algo esta medido, inferido, falldio o desconocido, para evitar allucinations". Every number in the benchmark carries one label: measured, inferred, failed, unknown. Unlabeled numbers are not reported.
- **S10 Deterministic scripts.** "La parte de los scripts que ayudan a tener resultados deterministas". Every metric comes from a script that two runs over the same input reproduce byte-for-byte; tests prove it.
- **S11 Lints.** "lints que permiten limpiar, comment, el codigo". Measure lint and comment-gate effect (what they block, how often, false positives).
- **S12 Multi-agent workflows.** "El manejo de workflows de multiagentes, como depterminar lso agentes". Measure how agents are chosen and used (subagent counts, roles, delegation reasons, cost share).
- **S13 Token consumption.** "Como va el consumo de tokens, y de tareas de proposito general a especifico". Tokens per task, split general-purpose vs specialized agents, before vs after.
- **S14 Router.** "como medir el router que se encarga de escoger lso modelos y el esfuerzo de cada uno". Measure the model/effort router: decisions, cost, quality per tier.
- **S15 Skills scalability.** "Como se peude integrar y escalar con nuevos skills, que formen parte de todo el proyecto." Report how skills are added and registered, with evidence of the cost of adding one.
- **S16 Ways of working.** "cuanto de esto se peude hacer como unways of work." Report which parts are transferable ways of working versus tooling tied to this setup.
- **S17 Delivery speed.** "que tan lento o rapido permite hacer delivery de producits". Lead time and throughput before vs after.
- **S18 MCP integration.** "Como se conecta con otros MCP". Report MCP integration points with evidence.
- **S19 Product framing and strict audit.** "velo como un producto a vender y mostrar a otros desarrolaldores y quiero medir que tanto realmente potencia en numeros y slides vs no tenerlo y quiero que se use la metodolofia agnositca para si mismo hacerse un becnhmark proque necesioto demostras que cosas works y cuales no y que tanti el bullshit, quiero la auditoria estricta que me permita demostrar si esta herramienta es util o no y mostrarla". Deliverables: audit report with numbers and a slide deck; the benchmark itself is run with the kit's own methodology (ODD doc, deterministic scripts, judges, epistemic labels).
- **S20 Phased evidence.** User chose "Ambos, en fases": Phase 1 retrospective mining (transcripts, git, Engram, hook ledgers) producing baseline + hypotheses; Phase 2 small controlled A/B (vanilla / kit / kit-without-Engram, seeded-defect tasks, repetitions, blind judges) confirming or killing each claim. Phase 2 starts only after a cost forecast and user approval.
- **S22 Context memory under multi-agent work.** "quiero ver como se comprota el manejo de la memoria de context con y sin la metodologia , pero con respecto a multiagentes tambein". Context handling is compared with vs without the kit, and separately for sessions with vs without subagents: parent peak context, subagent token share, context handed to each subagent, compactions, and what survives a compaction.
- **S21 Coordinator.** "sera util usar fable para lanzar la revisiond etodo esto?" / "al menos como coordinador" / "ya comenzamos ocon la fase 1 como coordinador de Fable 5.1". Fable 5.1 coordinates; it is never the model under test and never the sole judge.
