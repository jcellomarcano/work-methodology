## A/B runner (`b30a645..8ca42e7`)

- WARNING | R1-001 | 08-benchmark/lib/bench_ab.py:49-50 | The default allowlist grants Bash(git diff:*), Bash(git show:*) and Bash(git log:*) as 'read-only inspection', but git diff, show and log accept an --output option that writes to an arbitrary file path. A model run, for example one steered by prompt-injected content in the diff under review, could write outside the temp worktree, including into the user's checkout. That would break the module's guarantee that the user's working tree is never written. The comment says this allowlist mirrors bin/pr-review-ab.sh, so the pattern is carried over rather than new, and exploiting it needs adversarial model behavior. That makes it a hardening gap rather than a demonstrated exploit.
- WARNING | R4-orphaned-claude-on-interrupt | 08-benchmark/lib/bench_ab.py:250-268 | _run_process launches `claude -p` with start_new_session=True and only handles TimeoutExpired. A Ctrl-C (KeyboardInterrupt) during a long benchmark run propagates out of communicate() without killing the process group. Because the child sits in its own session, the terminal SIGINT never reaches it. run_one's finally block then force-removes the worktree while the orphaned `claude -p` keeps running, spending API cost for up to max_turns (default 80) and timeout_s (default 1800s), and writes into a deleted directory. The fix is to also kill the group in a BaseException handler (or try/finally) inside _run_process.
- WARNING | R4-batch-abort-no-resume | 08-benchmark/lib/bench_ab.py:456-463 | The run loop does not isolate per-run exceptions. Any exception that run_one does not convert into a record aborts every remaining planned run, for example a shutil.Error from copytree of an unreadable file in the kit `.claude/` overlay, or an OSError writing raw files. After the abort, the guard that refuses an existing runs.jsonl makes the same --out unusable, and there is no resume. A partial k x arms x tasks batch costing real API spend must therefore be restarted from scratch into a new directory. The fix is to record such exceptions as status failed with a reason, or to support resuming from the existing runs.jsonl.
- WARNING | R4-timeout-spend-undercounted | 08-benchmark/lib/bench_ab.py:350-352 | A timed-out run returns before any cost is recorded, so cost_usd stays None. The killed process never prints its JSON result. The report's spend_usd and cost_per_solved_usd then sum only runs with numeric cost_usd, labelled Measured. Timed-out runs, the longest and usually most expensive at up to timeout_s each, therefore silently drop out of the arm's spend. This contradicts the stated intent that failed runs are charged so cheap failures cannot hide. The cell should mark spend as a lower bound or Unknown when any failed run lacks a cost.
- WARNING | R2-001 | 08-benchmark/lib/bench_ab.py:177 | The judge timeout default is hard to follow and undocumented. judge_timeout_s falls back to the run's timeout_s when that key is set. When it is absent, the fallback is 600, while the run default is 1800. main_judge then repeats its own 600 fallback. A config that sets a long timeout_s for agent runs therefore gives every judge call that same long ceiling. Neither the example config's comment block nor the module docstring explains this.
- WARNING | R2-002 | 08-benchmark/protocols/ab-config.example.json:63 | The example kit-neutral evidence regex is a hand-copied, shortened duplicate of KIT_EVIDENCE. It leaves out the pre-port skill names that the preset matches. The drift test only compares the first 20 characters, so the two copies can diverge silently. A user who copies the example gets a stricter activation check than the preset, so the same transcript can be marked invalid-arm under one and ok under the other.
- SUGGESTION | R2-003 | 08-benchmark/lib/bench_ab.py:236-237 | Two functions repeat the same sys.path mutation plus optional import of transcript_metrics: _transcript_dir and _kit_words. A single helper would keep the skill-folder import rule in one place and make the side effect on sys.path explicit.
- WARNING | R3-001 | 08-benchmark/lib/bench_ab.py:393 | An arm's `evidence` regex from the config is compiled only after the paid `claude -p` run finishes. load_config never validates it. An invalid pattern raises re.error out of run_one. That aborts the whole `ab` loop after real API spend, and the spent run's record is never written to runs.jsonl. Compile `evidence` in load_config and raise ConfigError on failure.
- WARNING | R3-002 | 08-benchmark/lib/bench_ab.py:650-652 | Judge replies are model output, but the parser assumes their shape. A reply whose "A"/"B" value or "per_finding" value is not a dict (for example a string or a list) raises AttributeError. That crashes main_judge, and because judge.json is written only at the very end, every judgment already paid for in the run is lost. Shape-check the reply and record status failed with reason malformed-reply.
- WARNING | R3-003 | 08-benchmark/lib/bench_ab.py:171 | `repo` is used as given and is never normalized to the git toplevel. The example config's ".." resolves to a subdirectory of the checkout, and that causes two problems. First, `git worktree add` checks out the whole repo, but overlay sources are read from repo/<rel> and copied to the worktree root. Kit files at the real root are then reported as overlay_missing, and kit arms degrade to invalid-arm. Second, the guards that keep --out and the worktree outside the repo only compare against the subdirectory. A default ./bench-ab-<sha12> created from the checkout root then writes into the user's working tree, which the module says never happens.
- WARNING | R3-004 | 08-benchmark/lib/bench_ab.py:202-203 | Some invalid inputs escape the ConfigError and exit-2 path and end in a raw traceback instead of a clean error. A missing or unreadable `prompt_file` raises OSError, and non-integer `k`/`max_turns` raise ValueError; main_ab only catches ConfigError and CalledProcessError. Likewise main_judge reads config.json and runs.jsonl without the existence check that main_report performs.
- WARNING | R3-005 | 08-benchmark/lib/bench_ab.py:645-646 | No test exercises judge failure paths: timeout, launch failure, or an unparseable reply. No test exercises the `comparisons` config override either. Both stub judges always return well-formed JSON, so the failed/no-reply recording and its exclusion from agreement and validity are unproved.
- SUGGESTION | R3-006 | 08-benchmark/lib/bench_ab.py:651-652 | When a judge omits a finding id, that finding is silently dropped rather than counted as Unknown. judge_validity's denominator then shrinks, and a judge that skips the findings it doubts inflates the arm's validity.
