# Contributing to this methodology

This methodology follows its own rules. To propose a change:

1. Write a short change card for it ([04-templates/change-card.md](04-templates/change-card.md)) — why the change is needed, what it risks, how you'll know it worked.
2. Open a PR with the change card linked.
3. Keep docs short: each doc stays under ~150 lines, the README under ~200. If your change makes a doc grow past that, split it instead of letting it sprawl.
4. Prefer tables and checklists over prose.
5. Everything here is 100% English and project-agnostic — no company names, no client names, no mandatory tech stack.

Small wording fixes don't need a change card. Anything that changes a rule, a template, or a workflow step does.
